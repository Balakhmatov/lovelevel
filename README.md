# LoveLevel — версия для собственного VPS

Мобильный веб знакомств. Все анкеты доступны сразу; уровень управляет материалами галереи. Вход по email и паролю, SQLite и фотографии на диске VPS. Runtime не зависит от Sites, ChatGPT, Supabase или Cloudflare Workers. Cloudflare может оставаться DNS-провайдером домена.

## Возможности

Анкеты 18+, город и возраст, интересы, шкала уровней 0–100, серверная проверка доступа к фото, 12 фотографий с премодерацией, взаимные лайки, текстовая переписка, жалобы, блокировки, пауза и удаление аккаунта. Фотографии перекодируются в браузере до 1600 px без исходных метаданных. Личные оригиналы не раздаются статически.

Пароли хешируются scrypt с индивидуальной солью. Сессии — случайные токены в HttpOnly/SameSite cookie, Secure в production; база хранит только хеши токенов. Смена пароля отзывает другие сессии; выход отзывает текущую; удаление аккаунта удаляет учётные данные. Заголовки пользовательской личности от клиента отбрасываются, внутренняя личность формируется только из проверенной сессии. Администраторы назначаются по стабильным ID, никогда по непроверенному email.

Проверка email и автоматическое восстановление по почте пока не включены. Email служит логином. В закрытом тесте восстановление выполняет оператор после проверки личности через CLI со скрытым вводом пароля. Telegram-вход, видео, голос и платежи пока не подключены. Пользователь декларирует возраст, надёжной проверки возраста нет; откровенные материалы в этом тесте запрещены.

## Локальный запуск

Node.js >=22.13 с node:sqlite (проверено на 24.19). Для изменения схемы нужны dev-зависимости; на production для запуска не нужны npm-пакеты.

```sh
npm ci
npm run build
npm test
npm run dev
```

Открыть `http://127.0.0.1:3118`. Локальная база создаётся в игнорируемой `data/`; в production — `/var/lib/lovelevel/lovelevel.sqlite`. Фото — в `uploads/` внутри DATA_DIR. Только `127.0.0.1` допускает локальные cookie без Secure. Production обязан использовать HTTPS.

`npm test` проверяет доступ к медиа, матчи, чат, блокировку, реальную HTTP-авторизацию, подделку заголовков, пароли, сессии, сохранение после перезапуска, удаление и перенос данных. `scripts/browser-qa.mjs` проверяет регистрацию, вход/выход, создание анкеты, загрузку фото, прогресс, смену пароля и адаптивность через установленный в рабочей среде Playwright.

## Настройка

`deploy/app.env.example` содержит только имена и несекретные defaults. Настоящий файл — `/etc/lovelevel/app.env`, root:root, 0600:

- `PUBLIC_ORIGIN=https://lovelevel.cityai.site`
- `ALLOW_REGISTRATION=false` до проверки миграции и входа владельца; затем `true`.
- `INVITE_CODE` — необязательный код для регистрации тестировщиков; не публикуется в UI или Git.
- `ADMIN_USER_IDS` — ID администраторов через запятую.

Port 3118 и DATA_DIR выставляет отдельный systemd unit. Nginx перезаписывает X-Real-IP, сервис слушает только loopback. Существующие службы CityAI и Business Pulse не используются как обработчики LoveLevel и не перезапускаются.

## Развёртывание

Сначала код проверяется локально и упаковывается; доступ к VPS нужен отдельно, настройки прошлых проектов не являются SSH-подключением.

```sh
npm run build
npm test
node scripts/package-vps.mjs
```

Архив в outputs содержит server/, собранный интерфейс, миграции и deploy/. В нём нет пользовательских данных, паролей, SSH-ключей и dev-зависимостей. Перенести архив на VPS защищённым каналом и распаковать **в новый каталог `/opt/lovelevel/releases/<release-id>`**. Затем от root:

```sh
bash /opt/lovelevel/releases/<release-id>/deploy/install.sh /opt/lovelevel/releases/<release-id>
```

Установщик проверяет свободный порт и подходящий Node, создаёт пользователя lovelevel, отдельную службу и writable data directory, сохраняет предыдущую SQLite перед миграциями, проверяет `/health`. При ошибке возвращает прежнюю версию и резервную копию БД. Глобальный Node и другие приложения не меняются. Статические файлы и uploaded data не должны находиться в одном публичном каталоге.

Nginx настраивается отдельно после проверки сервиса:

```sh
bash /opt/lovelevel/current/deploy/configure-nginx.sh
```

Скрипт отказывается заменять чужой virtual host, проверяет nginx -t, при ошибке возвращает предыдущий файл. Применение — graceful reload Nginx, не restart.

После проверки сервиса и данных заменить **только CNAME lovelevel**, ведущий на Sites, на A-запись с реальным IP VPS. Не угадывать IP по домену за Cloudflare. При наличии AAAA проверить, что он также ведёт на этот VPS. Для HTTP-01 оставить DNS only до выпуска сертификата. Затем, если на VPS уже установлен certbot:

```sh
certbot certonly --webroot -w /var/www/lovelevel-acme -d lovelevel.cityai.site
bash /opt/lovelevel/current/deploy/configure-nginx.sh --https
```

Проверить HTTPS, реальный вход и загрузку/одобрение фото. Только затем открыть регистрацию тестировщикам. Старый Sites адрес до успешного перехода сохраняется как источник и резерв. Его hosted-версия и исходная main не изменены этой миграцией.

## Сохранение текущей анкеты и фото

В `transfer/sites-database.json` рабочей среды сохранён приватный снимок таблиц старого MVP. Каталог игнорируется Git и не входит в deploy-архив. Это **снимок БД, не полная копия фото**: перед импортом нужно дополнительно получить исходные файлы из старого хранилища в структуре `photos/<old-user-id>/<media-id>`.

Импорт поддерживает только пустую целевую базу. Если отсутствует хотя бы одно фото, есть неизвестные поля/таблицы или целевые данные уже существуют, импорт прекращается. При ошибке SQL вставки откатываются, скопированные файлы удаляются. Старый сервис во время окончательного экспорта должен быть без новых изменений; на целевом сервисе до окончания импорта регистрация закрыта.

Под пользователем lovelevel из `/opt/lovelevel/current`, с остановленной lovelevel-службой:

```sh
/usr/local/bin/node-lovelevel --experimental-sqlite server/import.mjs --snapshot /secure-transfer/sites-database.json --files /secure-transfer/files --dry-run
/usr/local/bin/node-lovelevel --experimental-sqlite server/import.mjs --snapshot /secure-transfer/sites-database.json --files /secure-transfer/files
/usr/local/bin/node-lovelevel --experimental-sqlite server/manage.mjs create-account --email OWNER_EMAIL --profile-id IMPORTED_PROFILE_ID
```

Пароль вводится скрыто или через stdin, никогда через argv. Привязка сохраняет ID профиля, прогресс и владение материалами. Выданный ID вручную добавить в ADMIN_USER_IDS; запустить только lovelevel. Не выдавать права по одному совпадению непроверенного email. Другие учётные записи можно создавать тем же CLI либо через регистрацию после её открытия.

## Состояние переноса

Код и пакет для VPS подготовлены. До получения SSH-доступа нельзя подтвердить установку на VPS, реальный IP, Nginx, сертификат или перенос файла из старого хранилища. DNS остаётся на прежнем размещении до проверки нового сервиса. Не объявлять перенос завершённым по локальным тестам.

## Автодеплой как у «Бизнес Пульса»

Основной путь установки и последующих обновлений теперь **GitHub → VPS timer**. См. [deploy/README.md](deploy/README.md). Ручная загрузка архива не требуется. Первичная установка — клонирование `Balakhmatov/lovelevel` в `/opt/lovelevel/repository` и запуск `deploy/install-poller.sh`. В дальнейшем проверенные изменения в main автоматически разворачиваются отдельным таймером. Исходники публикуются без данных из transfer/, локальных баз, секретов и hosting-идентификаторов прежнего прототипа.

## Telegram-вход и привязка существующей анкеты

Бот: `@lovelevel_app_bot`. Используется официальный Telegram Login Widget (HMAC-SHA256 по протоколу `core.telegram.org/widgets/login`), без запроса права отправлять сообщения. Домен `lovelevel.cityai.site` должен быть привязан к боту через `/setdomain` у BotFather.

После автодеплоя выполнить на VPS от root:

```sh
bash /opt/lovelevel/current/deploy/configure-telegram.sh
```

Скрипт скрыто запрашивает токен, проверяет getMe и совпадение username бота, сохраняет секрет только в `/etc/lovelevel/telegram.env` (root:root, 0600), добавляет systemd drop-in с EnvironmentFile и перезапускает только LoveLevel. Токен не передаётся через argv, не выводится, не попадает в GitHub или браузер. Nginx и другие приложения не меняются. Настройка требует исходящего HTTPS с VPS к api.telegram.org. Токен и содержимое telegram.env не присылать в переписку.

Сначала владелец входит **по email** и выбирает «Мой профиль → Привязать Telegram». Связь сохраняет существующий стабильный ID, анкету, прогресс и назначенные права. После этого можно выйти и войти через Telegram. Автоматического объединения по username или email нет; один Telegram может принадлежать только одному аккаунту LoveLevel. Если пользователь сначала создаст отдельный Telegram-аккаунт, привязка к другой анкете отклонится; произвольное объединение аккаунтов не реализовано.

Новые Telegram-пользователи проходят подтверждение возраста/правил и общий флаг регистрации/код приглашения. Telegram не передаёт email: для Telegram-only аккаунта хранится внутренний provider key `telegram:<id>` в идентификаторе учётной записи, который не принимается формой email-входа и не показывается как адрес. Пароля у такого аккаунта нет; это не подтверждение возраста или личности владельца.

Проверки включают подпись, срок 5 минут, защиту от повторного использования и одноразовый challenge с HttpOnly-cookie, привязанный к браузеру и текущему аккаунту при linking. Telegram user ID — источник идентичности; имя и username — только отображаемые данные. Таблицы связи/ожидания удаляются каскадно при удалении аккаунта.

Реальный внешний вход проверяется после настройки токена и домена BotFather. `scripts/telegram-browser-qa.mjs` проверяет UI и настоящие серверные сессии/подписи, подменяя только внешний widget тестовой реализацией; он не доказывает работу реального бота.

## Telegram Mini App

Адрес Mini App: `https://lovelevel.cityai.site/miniapp`. Это тот же продукт, аккаунты, база и галерея, что на сайте. SDK Telegram загружается только на `/miniapp`; обычный сайт не зависит от него. Кнопка возврата, раскрытие WebView и нижняя безопасная область подключены через SDK. Telegram Web разрешён как родитель фрейма через ограниченный CSP; обычный сайт сохраняет запрет встраивания.

После автодеплоя выполнить `bash /opt/lovelevel/current/deploy/configure-telegram.sh` на VPS. Скрипт проверит токен и username, вызовет `setChatMenuButton` и выставит кнопку **«Открыть LoveLevel»** с URL Mini App. Открыть `@lovelevel_app_bot`, нажать Start и кнопку меню. `/setdomain` для Mini App не нужен. Профильная кнопка Launch app и ссылка `?startapp` требуют отдельного включения Main Mini App у BotFather; текущая установка запускает Mini App из меню бота. Ответы бота на текстовые сообщения не реализованы.

Первый вход предлагает два явных варианта: существующий аккаунт по email с последующей привязкой Telegram в профиле либо новый аккаунт через Telegram после подтверждения 18+ и правил. Автоматическое создание аккаунта при простом открытии исключено. Повторное открытие после привязки входит в ту же анкету. Права модератора определяются только существующим серверным ID.

Backend проверяет исходную строку `Telegram.WebApp.initData` по HMAC-SHA256 с ключом WebAppData, возрастом до 10 минут и защитой от повторяющихся параметров. `initDataUnsafe` для идентичности не используется. Проверяется подписанный numeric user ID. Browser Widget и Mini App используют разные протоколы и разные типы одноразовых challenge; подтверждения одного нельзя применить к другому. Свежий одноразовый challenge нужен на каждый обмен на сессию. Одно действующее Mini App initData допускает восстановление сессии при перезагрузке, а не считается одноразовым Widget-подтверждением.

Для клиентов с ограниченными third-party cookies Mini App может получить случайный opaque session token после успешной авторизации. Он хранится только в памяти модуля страницы, передаётся в Authorization, не попадает в URL, localStorage или sessionStorage. В базе хранится только его хеш. Защищённые изображения загружаются с авторизацией в Blob URL, которые отзываются при удалении элементов. Выход отзывает выбранную bearer-сессию. Нативный браузер продолжает использовать HttpOnly-cookie; неподписанные данные Telegram не дают сессию.

`scripts/miniapp-browser-qa.mjs` проверяет SDK-контекст с заблокированными cookies: явный вход владельца, фото, привязку, восстановление после reload, прежний уровень/роль и отдельную регистрацию нового пользователя. SDK подменяется тестовым объектом с валидно подписанными fake-token данными. Реальные клиенты Telegram и выдача menu button проверяются после добавления настоящего токена на VPS.
